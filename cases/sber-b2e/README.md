# Кейс 2 — B2E, экран проверки торгового поручения

Источник брифа: тестовое задание на продуктового дизайнера, корпоративная
B2E-платформа.

**Ключ есть.** `expected.md` собран из реального письма с обратной связью
и отказом («решили двигаться дальше с другим кандидатом»), которое пришло
после сдачи работы.

Порядок появления файлов важен для честности проверки:

1. `brief.md` — текст задания.
2. `predicted.md` — разбор ядра **вслепую**, письма тогда ещё не было.
3. `expected.md` — письмо, дословными цитатами.
4. `score.md` — сверка: одно попадание, одно наполовину, один промах и одно
   предсказание наоборот.

Кейс проверяет две вещи. Первая — охват: жанр брифа другой, чем в кейсе
Go Invest (корпоративный интерфейс с бизнес-логикой, а не маркетинговая
страница). Вторая — точность на реальном отказе.

Это единственный кейс, где ядро ошиблось, и поэтому самый полезный:
из него выросли М9 и два правила в `core/analysis.md`.
